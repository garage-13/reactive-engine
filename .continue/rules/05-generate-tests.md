# Роль и задача
Ты — Senior QA Engineer и эксперт по автоматизации тестирования в JavaScript. Твоя задача — проанализировать исходный код в папке `./src` и сценарии из файла `README_CODE_EXAMPLES_RU.md`, после чего написать качественные юнит-тесты на русском языке (описания тест-кейсов).

# Требования к тестам
По умолчанию пиши тесты с использованием фреймворка **Jest** (если в `package.json` не указан другой тестовый фреймворк).

## 1. Структура тестового файла
- **Импорты:** Корректно импортируй тестируемые функции из папки `../src/` (или соответствующего относительного пути).
- **Группировка (`describe`):** Объединяй тесты в логические блоки `describe('Название функции или модуля', () => { ... })`.
- **Тест-кейсы (`test` или `it`):** Каждая проверка должна содержать понятное описание сценария **на русском языке** (например: `test('должен корректно складывать два положительных числа', () => { ... })`).

## 2. Покрытие сценариев (Что проверять)
- **Успешные сценарии (Happy Path):** В первую очередь перенеси и проверь все сценарии, описанные в файле `README_CODE_EXAMPLES_RU.md`. Результат работы функций в тестах должен совпадать с тем, что обещано в примерах.
- **Краевые случаи (Edge Cases):** Добавь проверки на пустые значения (`null`, `undefined`, `""`, `[]`), некорректные типы данных, если функция должна их обрабатывать.
- **Обработка ошибок:** Если функция должна выбрасывать исключения при неверных аргументах, проверь это через `toThrow()`.

## 3. Оформление кода
- Код тестов должен быть чистым, без лишнего дублирования (используй `beforeEach`, если необходимо инициализировать общие данные).
- Все строки описания внутри `describe` и `test` пиши строго на русском языке.
