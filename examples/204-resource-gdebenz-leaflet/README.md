## Применение принципов ООП: В разрезе Примера 204
### Инкапсуляция и Абстракция (Структура класса `MapLogic`)
В коде вы создаете класс `MapLogic`. Вместо того чтобы UI-компонент `MapExample` вручную дергал URL, передавал туда параметры и следил за отменой сетевых запросов (`abortSignal`), все это инкапсулировано (спрятано) внутри класса.
UI видит только верхнеуровневую абстракцию: свойство `stationsResource` для чтения и метод `updateBbox` для записи.
```
┌────────────────────────────────────────────────────────────────────────┐
│                          КЛАСС: MapLogic                               │
├────────────────────────────────────────────────────────────────────────┤
│ Внутреннее состояние и логика (Инкапсулировано внутри экземпляра)      │
│  - this.bbox: инкапсулирует реактивную строку '44.2097,33.2144...'     │
│  - асинхронный fetch: логика проксирования, сборки URL и обработки     │
│    ошибок скрыта внутри колбэка engine.resource()                      │
├────────────────────────────────────────────────────────────────────────┤
│ Публичный интерфейс (Абстракция для React-компонента)                  │
│  + stationsResource --> Отдает объект { loading, data, error }         │
│  + updateBbox(newBbox) --> Позволяет изменять состояние одной строкой  │
└────────────────────────────────────────────────────────────────────────┘
       ▲                                                  │
       │ logic.updateBbox(bboxString)                     │ useReactiveValue(logic.stationsResource)
       │ [Реактивная Запись]                              ▼ [Реактивное Чтение]
┌────────────────────────────────────────────────────────────────────────┐
│                        КОМПОНЕНТ: MapExample                           │
│  Знает только *что* сделать (обновить bbox или отрендерить АЗС),       │
│  но не знает деталей *как* устроен сетевой запрос и реактивный граф.   │
└────────────────────────────────────────────────────────────────────────┘
```

### Наследование (`MapLogic extends AbstractService`)
Класс `MapLogic` не строит систему реактивности с нуля. Он наследует её от базового класса `AbstractService`, который поставляется движком `@pravosleva/reactive-engine`.
```
                  ┌───────────────────────────────┐
                  │    КЛАСС: AbstractService     │ (Базовый класс из библиотеки)
                  ├───────────────────────────────┤
                  │ #engine: ReactiveEngine       │ Внедряет ссылку на ядро
                  │ + constructor(engine)         │ движка во все сервисы.
                  └───────────────▲───────────────┘
                                  │
                                  │ Наследование (extends)
                                  │
                  ┌───────────────┴───────────────┐
                  │       КЛАСС: MapLogic         │ (Ваш пользовательский класс)
                  ├───────────────────────────────┤
                  │ + bbox = this.engine.signal() │ Пользуется унаследованным
                  │ + stationsResource = ...      │ свойством `this.engine`
                  │ + updateBbox()                │ для построения графа.
                  └───────────────────────────────┘
```

### Полиморфизм (`engine.inject(MapLogic)`)
Движок `ReactiveEngine` спроектирован полиморфно. Метод `engine.inject()` умеет принимать любой класс, который является наследником `AbstractService`. Движку не важна конкретная реализация — работает ли класс с картами, корзиной товаров или авторизацией. Для движка они все полиморфно выглядят как «Сервисы», которые нужно инициализировать, связать с `ReactiveEngine` и логировать.
```
        ┌─────────────────────────────────────────────────────────┐
        │                 engine.inject(Service)                  │
        └────────────────────────────┬────────────────────────────┘
                                     │
                    Принимает любой класс-наследник
                                     ▼
        ┌─────────────────────────────────────────────────────────┐
        │   Вызывает базовые методы жизненного цикла / логирует   │
        └────────────────────────────┬────────────────────────────┘
                                     │
                       Полиморфный результат в UI:
            ┌────────────────────────┴────────────────────────┐
            ▼                                                 ▼
 logic: MapLogic (для карты)                       auth: AuthService (для профиля)
 { bbox, stationsResource }                        { userSignal, login() }
```

###  Композиция (Внедрение реактивных узлов и логики)
Вместо создания жестких подклассов (например, класса `LeafletMapStationFetchingBboxLogic`), движок использует композицию. Внутри класса `MapLogic` мы собираем поведение из независимых кирпичиков (узлов реактивности):
1. Мы внедряем узел типа `Signal` (`this.bbox`)
2. Мы внедряем узел типа Resource (this.`stationsResource`), передавая в него кастомную **асинхронную функцию получения данных** и подписывая его на `this.bbox`.
```
 ┌────────────────────────────────────────────────────────────────┐
 │                 КОМПОЗИЦИЯ ВНУТРИ MAPLOGIC                     │
 │                                                                │
 │  ┌──────────────────────────────────────────────────────────┐  │
 │  │ 1. Сигнал (Входной узел графа)                           │  │
 │  │    this.bbox = engine.signal('44.2097,...')              │  │
 │  └───────────────────────────┬──────────────────────────────┘  │
 │                              │                                 │
 │                              │ Передается как зависимость      │
 │                              ▼                                 │
 │  ┌──────────────────────────────────────────────────────────┐  │
 │  │ 2. Ресурс (Вычисляемый асинхронный узел графа)           │  │
 │  │    this.stationsResource = engine.resource(              │  │
 │  │       async (bboxValue, abortSignal) => { ... },         │  │
 │  │       this.bbox                                          │  │
 │  │    )                                                     │  │
 │  └──────────────────────────────────────────────────────────┘  │
 └────────────────────────────────────────────────────────────────┘
```

### Как замыкается реактивный цикл (Flow данных):
1. Пользователь двигает карту (`map.on('moveend')`)
2. Вызывается `logic.updateBbox(bboxString)`.
3. Инкапсулированный внутри this.bbox геттер/сеттер меняет значение и уведомляет реактивный граф.
4. Граф видит, что `this.stationsResource` зависит от `this.bbox`, переводит его в состояние `loading: true` (React-компонент мгновенно перерисовывает строку «Получение АЗС...»).
5. Выполняется композиционная функция с `fetch()`, данные возвращаются, и узел `stationsResource` обновляет свой `data: Station[]`.
6. Хук `useReactiveValue` триггерит обновление UI, срабатывает эффект отрисовки маркеров Leaflet.
