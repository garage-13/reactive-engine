# Пример 251: Цепочка ресурсов

Чтобы полностью портировать этот пример цепочки ресурсов на Vue 3 с разделением по файлам, нам не понадобится функция `createObserver`, так как Composition API во Vue 3 изначально реактивно отслеживает изменения на уровне атомарных Ref (в отличие от React, где для автоматического трекинга без явного `.use()` нужен HOC `observer`).
Мы сохраняем код сервисов `service.firstly.ts` и `service.secondary.ts` абсолютно идентичным, а изменения затронут только файл инициализации (`store.ts`) и сам UI-компонент.

Во Vue 3 для подписки на сложные асинхронные объекты (состояния ресурсов) мы прогоняем их через `vueEngine.use()`. А для того чтобы удобно читать вложенные свойства ресурсов (`.loading`, `.data`, `.error`) и списки (`personList`), мы используем вычисляемые свойства Vue (`computed`), что является стандартом разработки на Vue 3.

## Архитектурные преимущества этого решения во Vue 3:
1. Никаких HOC-оберток: Нам больше не нужно оборачивать компонент в `observer()`. Vue 3 самостоятельно перерисует только те части шаблона, чьи зависимости (computed или ShallowRef) изменились.
2. Идеальная реактивная цепочка (Reactive Chain): Когда вы нажимаете кнопку `userInfo.inc()`, ваше ядро сбрасывает `activePersonId`. Логика `SecondaryService` автоматически реагирует на сброс id через свое вычисляемое поле `apiDeps`, отменяет текущий асинхронный HTTP-запрос по `abortSignal`, очищает стейт (`resetDataOnSourceChange: true`) и выбрасывает ошибку 'Person id wasnt selected...'. И всё это происходит на уровне чистого TypeScript в кодовой базе ядра, а Vue просто визуализирует это состояние.
3. Чистота разметки: Директива `v-for` заменяет вызов `.map()`, сохраняя лаконичность HTML-дерева.
