# 📦 Демонстрация кластеризации микротасок (Example 109)

Этот пример наглядно иллюстрирует работу **атомарного батчинга (кластеризации)** реактивного ядра `ReactiveEngine` в связке с планировщиком `queueMicrotask` и адаптером React 18+.

## 🧐 В чём суть эксперимента?

В приложении выстраивается каскадная цепочка реактивных зависимостей по принципу **«Домино»**. Одно базовое состояние (`Signal`) порождает лавину каскадных вычислений в четырёх связанных свойствах (`Computed`), где каждое последующее звено зависит от результатов предыдущего:

```
[Signal: count]
↓
[Computed: step-A] (count + 10)
↓
[Computed: step-B] (step-A * 2)
↓
[Computed: step-C] (step-B - 5)
↓
[Computed: step-D] (step-C % 2 === 0)
```

## 🖥️ Анализ результата в консоли браузера (DevTools)

При нажатии на кнопку **«💥 ЗАПУСТИТЬ КАСКАД»** подсистема логирования ядра `flushLogs` перехватывает весь пак изменений и выводит в консоль **ровно одну свернутую мастер-группу**, подтверждая успешную кластеризацию транзакции:

```javascript
▼ 🟪 REACTIVE TRANSACTION Microtask Tick (Size: 5 | 0.245 ms) 🟢 stable
  ► 🟦 SIGNAL [example-109:signal:count] | 🔄 Изменений сигнала: 1
  ► 🟩 COMPUTED [example-109:computed:step-A] | 🟢 Стабильно (0.015ms)
  ► 🟩 COMPUTED [example-109:computed:step-B] | 🟢 Стабильно (0.012ms)
  ► 🟩 COMPUTED [example-109:computed:step-C] | 🟢 Стабильно (0.010ms)
  ► 🟩 COMPUTED [example-109:computed:step-D] | 🟢 Стабильно (0.022ms)
    [Execution Timestamp]: 14022.50 ms
```

### 🌟 Главные архитектурные преимущества:
1. **Размер батча (Size: 5):** Все 5 логов склеились в одну атомарную транзакцию. Спам изолирован.
2. **Консистентность UI:** React-компонент заходит на рендеринг **строго 1 раз** на самом финише микрозадачи, получая уже полностью вычисленные и синхронизированные данные.
3. **Профайлинг трендов:** Прямо в свернутом заголовке `console.groupCollapsed` разработчик видит суммарное время просчета каскада (`0.245 ms`) и динамику изменения перформанса (`🟢 stable`), что позволяет мгновенно заметить просадку скорости при усложнении формул.
