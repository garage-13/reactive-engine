## 🧠 1. JS Heap (Куча)
**Heap (куча)** — это специальная область в оперативной памяти компьютера, которую браузер выделяет под работу JavaScript.
- Зачем нужна: Каждый раз, когда в коде создается новый объект, массив, строка или инстанс класса, они физически сохраняются в кучу.
- **Как это работает в логах:**
  - `Used Heap` — это вес всех живых данных вашего приложения прямо сейчас.
  - `Allocated` — это резерв, который браузер откусил у операционной системы «с запасом».
  - Когда память заполняется, встроенный робот браузера — **Garbage Collector (сборщик мусора)** — синхронно сканирует кучу, находит мертвые объекты, на которые больше никто не ссылается (поэтому мы так бережно настраивали WeakRef), и стирает их. В этот момент полоса прогресса на дашборде резко отскакивает назад.

## ⏳ 2. Латентность (Latency / Event Loop Delay)
**Латентность** в контексте браузера — это задержка или «время ожидания» главного вычислительного потока JavaScript (**Event Loop**).
- Зачем нужна: JavaScript однопоточен. Это значит, что в один момент времени браузер может делать только что-то одно: либо выполнять тяжелую математику графа, либо обрабатывать клик пользователя, либо рисовать кадр анимации.
- **Как это работает в логах:** Если латентность равна `0-2 ms` — поток абсолютно свободен, интерфейс моментально откликнется на любое действие. Если латентность подскакивает до `30-100 ms` — это сигнал тревоги. Это значит, что какой-то синхронный кусок кода (например, тяжелый цикл или неудачный `JSON.stringify`) намертво заблокировал поток. В этот момент интерфейс начинает «тупить», а клики по кнопкам срабатывают с видимой задержкой.

## ⚡ 3. FPS (Frames Per Second)
**FPS** — это количество кадров, которое браузер успевает полностью отрисовать на экране за одну секунду.
- Зачем нужен: Это главный показатель плавности интерфейса (кинематографичности). Стандартом для современных мониторов является `60 FPS` (1 кадр каждые 16.6 миллисекунд), а для игровых или мобильных экранов — `120–140 FPS`.
- **Как это работает в логах:** FPS напрямую зависит от латентности. Если латентность растет, Event Loop не успевает вовремя отдать команду на отрисовку следующего кадра в requestAnimationFrame. Браузер вынужден выбрасывать («дропать») кадры. Если FPS падает ниже `45–50`, человеческий глаз начинает отчетливо видеть микро-фризы, рывки волны и подергивания интерфейса.
