# `/reactive-framework-test-suite` as GIT submodule
## Install
Если твой коллега впервые скачивает проект `@pravosleva/reactive-engine` с нуля, по умолчанию папка подмодуля будет пустой. Чтобы он мгновенно развернул и подтянул всё тестовое окружение бенчмарка, ему нужно выполнить при клонировании:

```bash
# Вариант А: Сразу клонировать основной проект вместе со всеми подмодулями
git clone --recursive <URL_ТВОЕГО_РЕПОЗИТОРИЯ>

# Вариант Б: Если проект уже склонирован без подмодулей — инициализировать их на месте
git submodule update --init --recursive
```

## 🔄 Инструкция по обновлению Git Submodule (Бенчмарка матрицы тестов)
Поскольку папка `report/reactive-framework-test-suite` является изолированным внешним Git-репозиторием, обновление его содержимого до свежих коммитов из ветки `master` родительского проекта выполняется отдельно от основного репозитория.

Выбери один из двух сценариев в зависимости от твоих целей:

### Сценарий 1. Быстрое обновление подмодуля одной командой
Если тебе нужно просто подтянуть последние изменения, отчёты или новые коммиты фреймворков из удаленной ветки бенчмарка, выполни в корне основного проекта:

```bash
git submodule update --remote --merge
```
*Что произойдет:* Git зайдет в папку подмодуля, сделает `git fetch` из оригинального репозитория бенчмарка и автоматически вольет (`merge`) свежие коммиты текущей ветки в твою локальную копию.

### Сценарий 2. Пошаговое ручное обновление с фиксацией коммита
Если тебе нужно зайти в бенчмарк, переключиться на конкретную ветку, тег или коммит и жестко зафиксировать эту версию для кодовой базы `@pravosleva/reactive-engine`:

```bash
# 1. Переходим в директорию подмодуля
cd report/reactive-framework-test-suite

# 2. Подтягиваем свежие данные и переключаемся на нужную ветку (например, master)
git checkout master
git pull origin master

# 3. Возвращаемся в корень основного проекта
cd ../..

# 4. Фиксируем обновленный указатель (коммит) подмодуля в основном проекте
git add report/reactive-framework-test-suite
git commit -m "chore(report): узел бенчмарка матрицы обновлен до актуального коммита"
```

### Отключение отслеживания изменений контента в `.gitmodules`
Даже если файлы прописаны в .gitignore, Git всё равно будет помечать сам подмодуль как измененный, если наш скрипт `update-readme.js` перезапишет в нём файлы тестов или README.

Чтобы сказать Git: «Мне плевать на изменения файлов внутри этой папки, следи только за самим коммитом подмодуля», открой файл `.gitmodules` в корне твоего проекта и добавь туда строчку `ignore = dirty`:
```
[submodule "report/reactive-framework-test-suite"]
	path = report/reactive-framework-test-suite
	url = https://github.com
	ignore = dirty
```
#### Что это даёт:
Флаг `ignore = dirty` — это спасение для работы с бенчмарками. Теперь твой скрипт автоматизации может генерировать внутри подмодуля гигабайты логов, устанавливать node_modules и перезаписывать README, но твой корневой проект будет оставаться идеально чистым в `git status`, показывая изменения только тогда, когда ты решишь обновить версию самого коммита бенчмарка!
