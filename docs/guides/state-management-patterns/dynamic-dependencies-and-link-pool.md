# Динамические зависимости и переиспользование связей (`LinkPool`)

В отличие от систем со статической топологией графа, **`@pravosleva/reactive-engine` v3.0.1** отслеживает зависимости динамически в момент исполнения кода. Если внутри `computed` или `effect` срабатывает условие `if / else`, граф мгновенно перестраивается под активную ветку.

## Как это устроено под капотом (GC-Free)

При переключении ветки исполнения движок решает две задачи одновременно — **защиту от лишних перерасчётов** и **экономию памяти**:

1. **Автоматическая отписка неактивных ветвей:** Сигналы, которые перестали читаться в новой ветке, полностью отцепляются от узла. Последующие мутации этих сигналов больше не будут будить вычисление или эффект.
2. **Пулинг рёбер `LinkPool`:** В версии **3.0.1** разорванные рёбра `NodeLink` не выбрасываются в кучу для сборщика мусора (Garbage Collector). Они обнуляются и возвращаются в статический пул `LinkPool`, откуда мгновенно извлекаются при подключении новой ветки.
3. **Курсор `depsCursor` за O(1):** Общие зависимости, которые читаются до развилки `if / else` (например, сам управляющий флаг), остаются на месте и подтверждаются курсором за **O(1)** без пересоздания.

## Практический пример: Переключение режимов «Черновик / Опубликовано»

Представим редактор документа, где в режиме черновика (`isDraftMode = true`) итоговый текст берётся из локального буфера автосохранения, а в режиме просмотра — из сервера. При этом локальный буфер может обновляться десятки раз в секунду при наборе текста.

```typescript
import { ReactiveEngine } from '@pravosleva/reactive-engine'

const engine = new ReactiveEngine()

// Управляющий флаг ветвления
const isDraftMode = engine.signal(true, 'editor:isDraftMode')

// Источники двух разных ветвей
const localDraftText = engine.signal('Черновой текст...', 'editor:localDraft')
const publishedServerText = engine.signal('Опубликованная статья', 'editor:published')

let computeCount = 0

// Динамический computed: подписывается только на активную ветку
const displayContent = engine.computed(() => {
  computeCount++
  return isDraftMode.value ? localDraftText.value : publishedServerText.value
}, 'editor:displayContent')

engine.effect(() => {
  console.log(`[Экран #${computeCount}]:`, displayContent.value)
})
// Стартовый вывод: [Экран #1]: Черновой текст...

// 1. Пользователь печатает в черновике -> эффект срабатывает
localDraftText.value = 'Черновой текст (правка 1)...'
// Вывод: [Экран #2]: Черновой текст (правка 1)...

// 2. Переключаем режим на «Опубликовано»
// Ребро на localDraftText уходит в LinkPool, создаётся ребро на publishedServerText
isDraftMode.value = false
// Вывод: [Экран #3]: Опубликованная статья

// 3. Фоновый процесс продолжает писать в черновик, но displayContent от него уже отписан!
localDraftText.value = 'Фоновое автосохранение в черновик...'
// Тишина! Ни computed, ни effect не потратили ни одного такта процессора (computeCount === 3).
```

::: tip Оптимизация порядка чтения в `computed`
Старайтесь читать стабильные управляющие флаги (например, `isDraftMode.value`) **в самом начале** функции `computed` или `effect` до ветвлений `if / else`. Тогда курсор `depsCursor` всегда будет попадать в быстрый путь (fast path) за **O(1)** для общих зависимостей и перестраивать только хвост списка после развилки.
:::
