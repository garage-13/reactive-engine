# Введение в Reactive Engine

`@pravosleva/reactive-engine` — это сверхлегкое, ультрапроизводительное логическое ядро и стейт-менеджер для современных приложений. Архитектура движка построена на концепции **сигналов (Signals)** и направлена на обеспечение предсказуемого потока данных с микрооптимизацией процесса рендеринга.

Главная цель движка — полностью изолировать бизнес-логику от UI-фреймворка, сократив количество обновлений компонентов до абсолютного минимума.

## Поддержка Tree-Shaking и независимость от React

Пакет спроектирован с учетом максимальной оптимизации размера бандла и полной поддержки **Tree-Shaking**. Благодаря архитектурному разделению точек входа на уровне `package.json`, использование базового ядра библиотеки (`@pravosleva/reactive-engine`) в Vanilla JS проектах или средах без графического интерфейса **абсолютно изолировано**. Код адаптеров React, а также сами зависимости фреймворка, физически изолированы в суб-пути `/react` и не попадут в вашу финальную сборку, если вы не импортируете их явно. Пакет `react` вынесен в блок `optionalPeerDependencies`, что гарантирует чистоту установки без лишних предупреждений пакетных менеджеров в не-React окружении.

## Ключевые особенности

* **Мгновенные атомарные обновления:** Компоненты подписываются не на абстрактный «объект состояния», а строго на конкретные примитивные сигналы (`Signal`) или вычисляемые свойства (`Computed`). Изменение значения обновляет *только* те элементы интерфейса, которые его выводят на экран.
* **Вычисления за O(1):** Производные состояния (`Computed`) ленивы по своей природе. Они кешируют результат и не запускают пересчет, пока не изменятся исходные сигналы, от которых они зависят.
* **Автоматический Batching (Пакетная обработка):** Множественные синхронные изменения состояний автоматически объединяются в одну микрозадачу. Тяжелые эффекты и сетевые запросы не будут перезапускаться циклично, если вы обновили 10 сигналов в рамках одного обработчика событий.
* **Умный контроль асинхронности:** Встроенный инструмент `resource` берет на себя оркестрацию `AbortController`. При изменении зависимостей движок автоматически отменяет предыдущие зависшие сетевые запросы, предотвращая состояние гонки (race conditions).

## Как это работает?

Движок реализует однонаправленный поток данных, полностью независимый от вашего UI (Vue, React, Angular):
```
[ UI Действие (Клик/Ввод) ] ──> Обновление Signal
                                       │
                                       ▼
                             [ Вычисление Computed ]
                                       │
                                       ▼
[ Микрооптимизированный UI рендер ] <── Эффект (Изменение DOM)
```

## Архитектурные блоки

Движок оперирует тремя базовыми сущностями:

1. **`Signal<T>`** — минимальная неделимая ячейка реактивного состояния (источник правды).
2. **`Computed<T>`** — ленивое вычисляемое значение, производное от других сигналов.
3. **`Resource<T, S>`** — реактивная обертка над асинхронными операциями (запросы к API, лонг-поллинг).

## Почему не стандартный стейт-менеджер?

| Традиционный подход | Подход Reactive Engine |
| :--- | :--- |
| При изменении одного поля перерисовывается всё дерево компонентов | Перерисовывается **только** конкретный текстовый узел, подписанный на сигнал |
| Инициализация внешних SDK (например, чата Edna) привязана к UI. При размонтировании компонента страницы скрипт загружается заново, теряется контекст выполнения, а логика отслеживания статуса инициализации размазывается по `useEffect` / `watch` | Скрипты внешних сервисов подключаются и оркеструются внутри изолированного Сервиса. Движок централизованно трекает статусы загрузки (`loading`, `ready`, `error`) через реактивные сигналы, атомарно предоставляя стабильный доступ к стороннему API из любой точки приложения независимо от маунтов/анмаунтов UI |
| Сложная интеграция бизнес-логики между разными фреймворками | Чистый JS/TS код, который за секунды переносится из React во Vue или NodeJS |
