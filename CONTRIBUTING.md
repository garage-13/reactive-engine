# Руководство по контрибьютингу (Contributing Guide)

Привет! Спасибо, что решил помочь в развитии `@pravosleva/reactive-engine`. Этот документ содержит правила разработки, архитектурные стандарты проекта и инструкции по запуску тестов.

## Локальное развертывание

1. **Клонируй репозиторий:**
   ```bash
   git clone https://github.com/garage-13/reactive-engine.git
   cd reactive-engine
   ```

2. **Установи зависимости:**
   Проект использует `yarn` в качестве основного пакетного менеджера.
   ```bash
   yarn install
   ```

## Архитектурные стандарты ядра

При внесении изменений в ядро системы (`src/core/core.ts`) строго соблюдайте следующие правила, чтобы не нарушить стабильность реактивного графа:

1. **Честный динамический трекинг зависимостей (Dynamic Dependency Tracking):**
   Любая реактивная сущность (включая `reactive()` ловушки) в фазе `get` обязана регистрировать функцию отписки в текущем эффекте (`currentEffect.cleanups.add`), если активен `engine.activeEffect`. Неактивные ветки зависимостей в рантайме должны очищаться автоматически.

2. **Асинхронный автобатчинг:**
   Изменения стейта (как Сигналов, так и свойств Proxy-объектов в ловушке `set`) не должны приводить к мгновенному синхронному перезапуску UI-эффектов. Обновления обязаны асинхронно накапливаться в `pendingEffects` и склеиваться в один UI-кадр через `queueMicrotask`.

3. **Защита V8 от бесконечных синхронных циклов (Set Loops Protection):**
   Никогда не итерируйтесь напрямую через `.forEach` по коллекциям `this.cleanups` или `propsSubscribers`, если внутри этого цикла возможна синхронная мутация графа. Всегда создавайте моментальный снимок коллекции с помощью `Array.from(collection).forEach(...)`. Это предотвращает мертвые блокировки (deadlocks) рантайма.

## Тестирование и контроль качества

Тестовая база проекта разделена на изолированные файлы по зонам ответственности. Это позволяет `Vitest` запускать тесты параллельно и изолировать работу со временем и сборщиком мусора.

### Структура тестовых файлов (`tests/`):
* `core.di.test.ts` — Тестирование DI-контейнера ядра ( provide / inject, фабрики, инстанцирование классов, обработка пустых токенов).
* `core.signals.test.ts` — Тестирование базовых примитивов (`Signals & Effects`, триггеры при мутациях, валидация рантайм-опций, функции очистки).
* `core.computed.test.ts` — Тестирование вычисляемых свойств (синхронный ленивый расчет Lazy Pull за O(1), подписки на изменения, метод `.destroy()`).
* `core.batch.test.ts` — Тестирование механизмов транзакций и пакетных обновлений (`engine.batch` и автобатчинг через `queueMicrotask`).
* `core.reactive.test.ts` — Тестирование глубокой Proxy-реактивности (вложенные свойства, кэширование Proxy через WeakMap, динамический трекинг и честное рантайм-ветвление подписок).
* `core.resource.test.ts` — Тестирование асинхронных ресурсов (`Network & Async Orchestration`, отмена через `AbortController`, повторные попытки с экспоненциальным бэкграундом и Jitter, защита от Race Conditions, микро-таймауты).
* `core.gc.test.ts` — Изолированное тестирование сборщика мусора и утечек памяти (`global.gc`, `FinalizationRegistry`, `WeakRef`-ссылки).

### Запуск тестов:

* **Стандартный прогон всех тестов:**
  ```bash
  yarn test
  ```

* **Запуск тестов с проверкой утечек памяти (Garbage Collector):**
  Тесты в файле `core.gc.test.ts` требуют явного флага Node.js для работы со сборщиком мусора. Запускайте их так:
  ```bash
  yarn test --expose-gc
  ```

### Важные правила написания асинхронных тестов:
1. **Тестирование Proxy-мутаций:** Поскольку свойства `reactive()` объектов батчатся асинхронно, после изменения стейта в тесте обязательно делайте паузу перед проверками `expect`:
   ```typescript
   store.a = 10;
   await new Promise<void>((resolve) => queueMicrotask(() => resolve()));
   expect(effectSpy).toHaveBeenCalledTimes(2);
   ```
2. **Изоляция Event Loop в адаптерах (React, Vue, Angular):** При эмуляции уничтожения контекстов фреймворков (`onDestroy`, `scope.stop()`), чтобы избежать зависания асинхронных хэндлов Vitest, прочищайте макрозадачи Node.js в самом конце теста:
   ```typescript
   await new Promise((r) => setImmediate(r));
   ```
3. **Работа со временем в `Resources`:** Нативный `AbortSignal.timeout(ms)` в Node.js игнорирует фейковые таймеры Vitest. В тестах таймаутов ресурсов используйте реальное время `vi.useRealTimers()` в сочетании с асинхронными утилитами ожидания `vi.waitFor`. В тестах повторных попыток (Retry Support), где нет `AbortSignal.timeout`, используйте `vi.useFakeTimers()` и `vi.runAllTimersAsync()`.

## Оформление Пул-Реквестов (PR Workflow)

1. Создай новую ветку от `main` с понятным названием: `git checkout -b feat/your-feature` или `git checkout -b fix/bug-name`.
2. Напиши код, следуя правилам линтера (`yarn lint`).
3. Покрой изменения тестами в соответствующем доменном файле. Убедись, что **все 82 теста** проходят успешно.
4. Оформи коммит по стандарту **Conventional Commits** (например, `fix(core): patch proxy get trap for dynamic cleanups`).
5. Открой Pull Request и дождись прохождения проверок на CI.
